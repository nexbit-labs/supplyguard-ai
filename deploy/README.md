# Deployment notes (U-12)

Local stack: see `docs/INSTALL.md`. This file covers exposing local services to Boomi (S1) and hosting (S4).

## S1 - Tunnel the local mock ERP / backend to the Boomi cloud atom

The Boomi cloud atom cannot reach `localhost`. Expose the local services over HTTPS.

1. Secure the mock ERP first. In `.env` set a long random key and restart:
   ```
   MOCK_ERP_API_KEY=<long random string>
   MOCK_ERP_ENABLE_TEST_ENDPOINTS=false   # true only if the demo needs reset/chaos endpoints
   ```
   `docker compose up -d mock-erp`. NEVER tunnel with an empty `MOCK_ERP_API_KEY`.
2. **REQUIRED before tunnelling the backend** (skip only if you tunnel the mock ERP alone). In `.env` set:
   ```
   DEBUG=False
   SECRET_KEY=<output of: python -c "import secrets;print(secrets.token_urlsafe(50))">
   ALLOWED_HOSTS=localhost,127.0.0.1,backend,<tunnel-host>
   CSRF_TRUSTED_ORIGINS=https://<tunnel-host>
   BEHIND_HTTPS_PROXY=True
   ```
   Then `docker compose up -d backend`. **Never tunnel the backend with DEBUG=True or an example/empty SECRET_KEY: anyone could forge JWTs and see public tracebacks.**
3. Start a tunnel (recommended: cloudflared quick tunnel, no account needed):
   ```
   cloudflared tunnel --url http://localhost:8081      # mock ERP
   cloudflared tunnel --url http://localhost:8000      # backend (separate terminal, if Boomi must call it)
   ```
   Alternative: `ngrok http 8081`. Each run prints a random `https://...` URL that changes on restart.
4. Check: `/health` is unauthenticated and proves nothing about auth. Verify with `curl https://<url>/erp/suppliers/<id>`: it must return 401 without the key and 200 with `-H "X-Api-Key: <key>"`. Boomi must send `X-Api-Key` on every call to the mock ERP, plus `X-Tenant-ID` (required on PATCH).
5. Record the URL as a Boomi **environment extension** (Manage > Environment Extensions > Connections / process properties), e.g. `MOCK_ERP_URL` and `MOCK_ERP_API_KEY` (password type). Do not commit URLs or keys to git; update the extension whenever the tunnel URL changes.
6. Stop the tunnel when not demoing.

## S4 - Hosted plan (Render)

`deploy/render.yaml` is a Render Blueprint: managed Postgres 16, backend (docker, `./backend/Dockerfile`, context `./backend`), mock-erp (docker, `mock-erp/Dockerfile`, repo-root context, `PORT=8081`), frontend static site.

**UNTESTED until a Render account exists.** Expect small fixes on first apply.

Steps:
1. Render dashboard > New > Blueprint > pick the repo, set blueprint path `deploy/render.yaml`.
2. `SECRET_KEY` and the mock ERP `MOCK_ERP_API_KEY` are generated by Render (the backend receives the key via `fromService`; read it from the mock-erp service env for Boomi). Set `MOCK_ERP_URL`, `CORS_ALLOWED_ORIGINS` (frontend URL), `CSRF_TRUSTED_ORIGINS` (backend https URL) and `VITE_API_BASE_URL` (backend URL + `/api/v1`) once the service URLs are known, then redeploy.
3. The free plan has no `preDeployCommand`: migrations run in the start command (`migrate && gunicorn`). `RENDER_EXTERNAL_HOSTNAME` is added to `ALLOWED_HOSTS` automatically; `BEHIND_HTTPS_PROXY=True` is set in the blueprint.
4. Put the hosted mock-erp URL + key into the Boomi environment extensions.

Follow-ups / known gaps:
- With `DEBUG=False`, Django admin static files are not served by gunicorn. Add `whitenoise` (middleware + `STORAGES`, `collectstatic` in the build) in `backend/` - not done to avoid new dependencies. The API itself is unaffected.
- Local compose runs `runserver` (dev, auto-reload); `backend/Dockerfile` CMD is production gunicorn running as a non-root user. The blueprint start command adds migrate before gunicorn.
- Render free services sleep after ~15 min idle (~1 min cold start) and the in-memory mock ERP resets to its seed data on wake. The live demo needs a paid plan or a keep-warm ping.
- Render free Postgres expires; use a paid plan for anything beyond the demo.
