## 1. Conventions

- IDs: string, prefixed - `SUP-1008`, `PO-1001`, `EVT-000123`, `RC-000045`, `REC-...`, `APR-...`, `EXE-...`.
- Timestamps: ISO-8601 UTC (`2026-12-02T10:15:00Z`).
- Money: `{ "amount": "420000.00", "currency": "INR" }` (decimal as string).
- Every request/response carries `X-Correlation-ID` (UUID v4). Django generates it if absent; Boomi must pass it through to every call and event.
- Tenant: **never** taken from body/query. Users -> JWT claim `tenant_id`. Boomi/system callers -> API credential mapped to a tenant (`X-Api-Key` -> tenant).
- Error body (all services):
  ```json
  { "error": { "code": "VALIDATION_ERROR", "message": "human readable", "details": {}, "correlation_id": "uuid" } }
  ```
  Codes: `VALIDATION_ERROR` (400), `UNAUTHENTICATED` (401), `FORBIDDEN` (403), `NOT_FOUND` (404), `CONFLICT` (409, e.g. invalid state transition / duplicate), `BUSINESS_RULE` (422), `DOWNSTREAM_ERROR` (502), `DOWNSTREAM_TIMEOUT` (504).

## 3. Canonical disruption event (Event Streams topic `supplier.disruption`, and `POST /api/v1/events/disruptions`)

```json
{
  "event_id": "EVT-000123",
  "tenant_id": "TEN-ACME",
  "supplier_id": "SUP-1008",
  "event_type": "FACTORY_OUTAGE",
  "severity": "HIGH",
  "event_time": "2026-12-02T10:15:00Z",
  "expected_duration_hours": 48,
  "description": "Line 2 fire, production halted",
  "source_system": "supplier-portal",
  "correlation_id": "6f1c..."
}
```
- `event_type`: `FACTORY_OUTAGE | SHIPMENT_DELAY | QUALITY_HOLD | CAPACITY_REDUCTION | LOGISTICS_DISRUPTION`
- `severity`: `LOW | MEDIUM | HIGH | CRITICAL`
- `tenant_id` in the payload is informational only; the trusted value comes from the credential and they must match, else 403.
- Duplicate `event_id` -> `200` with the existing `correlation_id` and `risk_case_id` (no new case).

Other topics: `shipment.delay` (same shape, `event_type=SHIPMENT_DELAY`, plus `shipment_id`, `po_id`), `recovery.status` (`{risk_case_id, execution_id, status, correlation_id, time}`).

## 7. RiskCase state machine (Nikhil owns transitions, everybody uses it)

```
RECEIVED -> ANALYZING -> RECOMMENDATION_READY -> PENDING_APPROVAL -> APPROVED -> EXECUTING -> RECOVERED -> CLOSED
                                                      |                              |
                                                      v                              v
                                                  REJECTED -> (ANALYZING | CLOSED)   EXECUTION_FAILED -> (EXECUTING via retry | CLOSED)
```
Only `apps.workflow.services.transition(case, to_state, actor)` may change state. It writes an AuditEvent every time. Invalid transition -> `409 CONFLICT`.

## 10. Entities (Django models) - DRAFT 0.3, added by U-03, table approval pending in the U-03 PR
Rule from S-01 (D-10.1, approved by Roop and Nikhil 2026-11-23): where a field appears in an API response the API name wins (sections 3-6, else `frontend/src/api/types.ts`); otherwise the LLD 16.1 name. Fields below are **model field names**; where the API shows a different name it is written `-> api_name`. Derived values are computed in the API and never stored. Reviewed by the opus reviewer on 2026-11-23 (3 blockers fixed in this version).

**Structure and rules**
- Apps (all in Uday's stream; Nikhil's `workflow` / `intelligence` hold logic, not tables): `tenants` = Tenant; `accounts` = User; `core` = everything else; `audit` = AuditEvent.
- `TenantOwned` (abstract, `apps.core`): `tenant` FK (PROTECT) and `created_at`. **Tenant-owned:** every model except `Tenant`, `User` (nullable `tenant` for superusers only), `AuditEvent` (nullable `tenant`) and `IdSequence`.
- **Same-tenant guard:** `TenantOwned.save()` checks that every FK target has the same `tenant_id` as the row (for `Approval.decided_by` this is `User.tenant`). Child rows (line, AffectedPO, Recommendation, Approval, Execution, AgentRun) copy `tenant` from their parent when unset; a mismatch raises. `bulk_create` and `QuerySet.update` skip this, so a caller that uses them must check itself. One test iterates over every tenant-owned model. Lookups by an external id are always `(tenant, id)`, e.g. `DisruptionEvent.objects.get(tenant=t, event_id=x)`; "exists in another tenant" answers exactly like "not found".
- **Ids.** ERP-originated records (Supplier, PurchaseOrder, Shipment) have a surrogate primary key and a business id `erp_id` with `UniqueConstraint(tenant, erp_id)`; the API shows `id` = `erp_id` (`SUP-1001`). The same id in two tenants is therefore legal and can never overwrite or reveal another tenant's row. The externally supplied `event_id` is likewise unique per tenant. System-generated ids (`RC-`, `REC-`, `APR-`, `EXE-`) are string primary keys from `IdSequence` (global counter: ids are not contiguous and one tenant could infer another's case volume, accepted for v1). `User` keeps its integer pk; the API shows `id` as `USR-<n>` through one helper that formats and parses it; the JWT `user_id` claim is the integer.
- Money: `DecimalField(14, 2)` plus a 3-letter currency column, serialised as `{amount, currency}`. Prices that come from snapshots (`unit_price`) are `Decimal(14, 4)`; everything else rounds half-up to 2 dp on write (D-1.2). Never `float`.
- Statuses and enums are `CharField` with choices. Ids are not regex-enforced in the database (the patterns in `ai/schemas/common.schema.json` stay the validation rule). Every list model has a `Meta.ordering` that makes pagination stable.

**RiskCase.status is guarded.** `status` may only change inside `apps.workflow.services.transition()`: the model remembers the loaded value, `save()` raises if `status` changed without the `status_change_allowed()` context manager (which only `transition()` uses), the manager's `update()` rejects a `status` keyword, and the admin shows it read-only. `transition()` locks the case with `select_for_update`. **Needs Nikhil's agreement** (open point 7), because `transition()` is his function and must use the hook.

**Not stored in Django:** alternate suppliers (the ERP is the source and the stored `snapshot` embeds them; add a table only if a Django reader appears), supplier `disruption_history`, KPIs and counts (computed), `retryable`.

**Seed loader (`manage.py load_seed [--data-dir PATH] [--demo-users]`):** one `transaction.atomic`, in order tenants, suppliers, purchase orders + lines, inventory, shipments. Idempotent: get the row by `(tenant, erp_id)` or natural key and update in place; never `update_or_create` on a key that ignores the tenant; abort if a row would change tenant. Lines upsert on (po, line_no) and lines missing from the seed are deleted; POs are never deleted. Renames: `tenant_name` -> `name`, `supplier_id` / `po_id` / `shipment_id` -> `erp_id`. Skips `disruption_history` and `alternate_suppliers.json`. Money via `Decimal(str)`; checks line currency = PO currency = tenant currency, `amount` = sum of `qty x unit_price`, `expected_date` = latest line `due_date`, `location_id` in the tenant's `locations`, `shipment.po` and `shipment.supplier_id == po.supplier` in the same tenant; fails loudly on any mismatch; the loaded totals for tenants, suppliers, purchase orders, inventory and shipments are compared with `manifest.json` (2 / 100 / 500 / 187 / 20); the line total (806) is only reported, because the manifest has no line count. Inside Docker the `data/` folder is mounted read-only at `/data`, so `docker compose exec backend python manage.py load_seed` works without options. No users by default. `--demo-users` creates one admin / procurement / viewer per tenant (usernames per tenant, e.g. `acme.admin`), takes the password only from `DEMO_USER_PASSWORD` (validated, never logged, existing passwords not reset). `--data-dir` loads the re-anchored `--as-of` seed (same ids, new dates, updated in place).

**Names that differ from the provisional frontend types** (Roop maps them in R-02; the left name is the model/API name): `risk_level` (not `severity`; the `?severity=` filter applies to it), `exposure_amount` (not `exposure`) on cases, `affected_qty` / `estimated_delay_days` / `exposure_amount` / `inventory_coverage_days` (not `qty` / `days_late_estimate` / `value` / `stock_cover_days`) on affected POs, `timestamp` (not `at`) on audit events. `decided_by` / `decided_at` are kept. **No Django source:** the UI's supplier `quality_pass_pct` (the seed has `quality_score` on a 0-5 scale), `avg_lead_time_days` and supplier `risk_score`: rename the field or accept null; nothing is invented.
